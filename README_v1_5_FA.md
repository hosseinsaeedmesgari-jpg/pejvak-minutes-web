# PEJVAK Minutes v1.5 — ارسال درخواست امضای اختصاصی

این بسته فقط برای **به‌روزرسانی پروژه موجود** است؛ نیازی به ساخت مخزن جدید نیست.

## قابلیت‌های جدید
- آدرس عمومی صفحه PEJVAK Sign به‌صورت پیش‌فرض در اپ اندروید: https://hosseinsaeedmesgari-jpg.github.io/pejvak-minutes-web/sign.html
- دکمه «ارسال درخواست امضا» مقابل نام هر امضاکننده در نسخه اندروید و وب
- ساخت لینک اختصاصی شامل نام، سمت و شماره صورتجلسه در قطعه `#` آدرس (بدون ارسال جزئیات جلسه به سرور GitHub Pages)
- آماده شدن پیام دعوت برای واتساپ، تلگرام و سایر برنامه‌های اشتراک‌گذاری
- تکمیل خودکار فیلدهای نام، سمت و شماره جلسه در صفحه sign.html، بدون تأیید خودکار یا ارسال امضا
- حفظ گزینه لینک عمومی و امکان اصلاح آدرس سایت در صورت تغییر آدرس میزبان
- تغییر نسخه Service Worker برای دریافت به‌روزرسانی توسط وب‌اپ‌های نصب‌شده

## نصب
1. از داده‌های موجود برنامه فایل پشتیبان JSON بگیرید و در جای امن نگه دارید.
2. در GitHub Desktop مخزن مرتبط را انتخاب کنید و Repository → Show in Explorer بزنید.
3. محتوای همین ZIP را در ریشه مخزن مربوطه کپی کنید. **هیچ فایلی از مخزن دیگر کپی نکنید.**
4. در GitHub Desktop تغییرات را Commit و با Push origin معمولی ارسال کنید (Force Push نزنید).
5. برای نسخه وب، Deploy موفق GitHub Pages را بررسی کنید. برای نسخه اندروید، Build موفق GitHub Actions و APK خروجی را بررسی کنید.
6. نسخه وب را پس از Deploy یک‌بار Refresh کنید و در صورت نمایش نسخه قبلی، کش PWA را به‌روزرسانی کنید.

## شیوه استفاده
1. یک جلسه جدید/موجود را باز کنید و **شماره صورتجلسه** را وارد کنید.
2. در بخش امضا روی «ارسال درخواست امضا» مقابل نام شخص بزنید.
3. لینک اختصاصی را بررسی و اشتراک‌گذاری کنید. **PDF صورتجلسه را جداگانه و فقط برای شخص مجاز ارسال کنید.**
4. دریافت‌کننده، صفحه PEJVAK Sign را باز می‌کند؛ نام/سمت/شماره جلسه از لینک پر می‌شوند و او باید تطابق را بررسی کند.
5. شخص پس از مطالعه و موافقت، امضا را رسم می‌کند و فایل JSON یا PNG را برای شما می‌فرستد.
6. فایل را در قسمت «بارگذاری امضا» فرد مربوطه وارد کرده و پیش‌نمایش PDF را بررسی کنید.

## حریم خصوصی و محدودیت‌ها
- این نسخه همچنان بدون سرور حساب کاربری یا پایگاه داده کار می‌کند و امضاها خودکار همگام نمی‌شوند.
- نام، سمت و شماره جلسه داخل آدرس اشتراک‌گذاری قرار می‌گیرند و برای دریافت‌کننده و پیام‌رسان قابل مشاهده‌اند؛ ولی متن و مصوبات جلسه در لینک نیست.
- از fragment (#) استفاده شده تا نام و شماره جلسه در درخواست HTTP به GitHub Pages ارسال نشوند، ولی خود پیام‌رسان می‌تواند محتوای URL را ببیند.
- ثبت یک امضای تصویری اثبات هویت امضاکننده یا امضای دیجیتال گواهی‌شده نیست.
- این بسته **خودِ APK نیست**؛ APK باید در GitHub Actions کامپایل شود.

## بررسی‌های انجام‌شده
- نحو جاوااسکریپت در نسخه اندروید و وب و صفحه امضا بررسی شد.
- ساخت لینک اختصاصی، آماده‌سازی متن ارسال، لینک عمومی، رفتار پیش‌فرض در WebView آفلاین، پرشدن فیلدهای صفحه امضا و نسخه کش PWA با تست‌های منطقی بررسی شدند.
- Build واقعی APK، نصب روی گوشی و بارگذاری نسخه وب در GitHub Pages هنوز باید بعد از Push آزمایش شوند.
